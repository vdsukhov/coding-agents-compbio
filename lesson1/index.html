Coding agents for computational biology · Lesson 1 of 5

Every answer is built one token at a time

A large language model does one thing: given some text, it scores every possible next piece of text and picks one. Chat, memory and "thinking" are all built on that loop. This lesson takes the loop apart, then has you call a local model from Python.

    10–35 min · Next-token prediction

    One job: predict the next token

    A neural network reads the text so far as a list of numbers and outputs a score for every token in its vocabulary. The scores become probabilities, one token is chosen, and it is appended to the input. Then the whole network runs again for the next token.

    Training sets the network's billions of weights so that, across trillions of tokens of text, the true next token gets a high probability. Nothing else is learned directly. Grammar, facts and marker genes all emerge because they help predict text.

    Temperature turns scores into choices

    The network's raw scores are called logits. Softmax turns them into probabilities, and temperature T divides the logits first. Low T sharpens the distribution toward the top token. High T flattens it, so unlikely tokens get picked more often. This is why the hook demo gave two answers.

    Why it is called temperature

    This formula is the Boltzmann distribution from physics, with each token's energy set to minus its logit, \(E_i = -z_i\). A high logit is a deep, low-energy well, and temperature sets how often particles escape it.

    Particles in an energy landscape · one well per token
    0.80

    Each particle is one sampled answer, and each well is a token whose depth comes from its logit. The bars count particles per well; the line across each bar is the softmax probability they settle around. Temperature and logits are shared with the explorer and the sampling demo below.

    Cold · \(T \to 0\)Particles freeze in the deepest well. The model picks its top token every time.
    Warm · \(T = 1\)Particles jiggle and sometimes hop. The model samples the distribution it learned.
    Hot · \(T \to \infty\)Particles boil over every barrier. Every token approaches \(1/V\), and output turns random.

    Cold model, frozen answers. Hot model, boiling answers.

    Low temperature pushes nearly all probability onto the top-scoring token. High temperature flattens the probabilities until every token is about equally likely. Subtracting the same number from every logit leaves the probabilities unchanged, which is why only the gaps between logits matter.

      Attention: which earlier tokens matter

      Inside each transformer layer, attention lets every token gather information from the tokens before it. To predict what follows "are", the model needs "Cells" and the gene names, not "that". A token can never look at tokens after it.

      Click a token to see where it looks

      Weights are illustrative. A real model has dozens of attention heads per layer, each with its own pattern.

      Pretraining, then instruction tuning

      A model trained only on documents continues documents. Given a question, it often writes more questions, because that is what text full of questions looks like. Instruction tuning then trains on conversations with good answers, so the most likely continuation becomes a helpful reply. Both are still next-token prediction.

      35–45 min · Tokenization

      Models read tokens, not letters

      Before the network sees anything, a tokenizer cuts text into pieces from a fixed vocabulary and replaces each piece with an integer. Common English words are one token each. Gene symbols and DNA are rare in training text, so they shatter into many small pieces.

      Two consequences matter for biology. Models are bad at letter-level tasks, such as counting bases or reversing a sequence, because they never see the letters. And sequences are expensive: you pay for context and time per token.

      This tokenizer is a simplified stand-in written for the lesson. Real BPE tokenizers learn their vocabulary from data and split text differently, but they break gene names and DNA into pieces in the same way. English prose averages about 4 characters per token.

      Ask a model how many r letters are in "strawberry" and it often gets the count wrong. The tokens show why: the model receives three token IDs, not ten letters.

      45–55 min · Context

      The context window is the only memory

      The model keeps nothing between requests. A chat app resends the whole transcript every turn: system prompt, every question, every answer. The context window is the maximum number of tokens one request can hold. When the transcript outgrows it, the oldest messages are dropped and the model never sees them.

        What the model actually receives

        The API takes a list of messages, but the model reads one long token sequence. A chat template joins the messages with special tokens, and the model simply continues after the last line.

        55–62 min · Thinking mode

        Thinking is more tokens before the answer

        A reasoning model first writes intermediate text, then the answer. Nothing new happens inside: it is the same next-token loop. The extra tokens give later tokens more to attend to, which helps on problems with several steps. You pay in time and context.

        62–85 min · Hands-on

        Talk to a local model from Python

        LM Studio runs a model on your laptop and serves it over HTTP with the same request format as OpenAI's API. Your Python code sends a list of messages and gets one new message back. No API key and no data leaves the machine.

        First call

        first_call.py
        from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")  # any key works locally
MODEL = "qwen/qwen3-4b"  # use the identifier LM Studio shows for your model

resp = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "system", "content": "You are a concise bioinformatics assistant."},
        {"role": "user", "content": "Which cell type expresses CD14, LYZ and S100A8?"},
    ],
    temperature=0.7,
)
print(resp.choices[0].message.content)
print(resp.usage)  # prompt_tokens, completion_tokens, total_tokens

        Exercises

        1. Build the chat yourself

          Keep the messages list in your own code and append every turn. This list is the context: watch prompt_tokens grow each turn.

          chat.py
          from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")
MODEL = "qwen/qwen3-4b"

messages = [{"role": "system", "content": "You are a concise bioinformatics assistant."}]
while True:
    user = input("you> ")
    if user in {"exit", "quit"}:
        break
    messages.append({"role": "user", "content": user})
    resp = client.chat.completions.create(model=MODEL, messages=messages)
    reply = resp.choices[0].message.content
    messages.append({"role": "assistant", "content": reply})
    print("model>", reply)
    print(f"[sent {resp.usage.prompt_tokens} tokens this turn]")

        2. Temperature 0 versus 1

          Send the hook prompt five times at each temperature and compare. At 0 the answers usually repeat word for word; at 1 they drift.

          sampling.py
          q = [{"role": "user", "content":
      "Cluster markers: CD14, LYZ, S100A8, S100A9, FCN1. Cell type? One line."}]

for t in (0.0, 1.0):
    print(f"--- temperature {t}")
    for _ in range(5):
        r = client.chat.completions.create(model=MODEL, messages=q,
                                           temperature=t, max_tokens=40)
        print(r.choices[0].message.content.strip())

Depending on LM Studio's overflow setting, older text is dropped or the request fails. Either way, the model cannot use what does not fit.

        4. Count tokens

          Compare a 50-gene list with a 1 kb FASTA sequence. The count includes a few tokens of chat-template overhead, so measure an empty message too and subtract it.

          count_tokens.py
          def count_tokens(text: str) -> int:
    r = client.chat.completions.create(
        model=MODEL, messages=[{"role": "user", "content": text}], max_tokens=1)
    return r.usage.prompt_tokens

overhead = count_tokens("")
genes = "IL7R, CCR7, CD14, LYZ, MS4A1, CD8A, GNLY, NKG7, FCGR3A, PPBP"  # extend to 50
print("genes:", count_tokens(genes) - overhead)
print("fasta:", count_tokens(open("seq.fa").read()) - overhead)
