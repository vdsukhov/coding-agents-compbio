Coding agents for computational biology · Lesson 1 of 5

Every answer is built one token at a time

A large language model solves one problem: given some text, predict what comes next. Chat, memory and "thinking" are all built on that. This lesson starts from the problem itself, works up to how a model learns and how it picks its words, then has you call a local model from Python.

    The problem

    What comes next?

    Forget neural networks for a moment and look at the task itself. You see the start of a text and have to guess how it continues. That is the whole problem a language model solves, one piece at a time.

    Try it. Guess the missing word in each line before you reveal what a model would say.

    Guess the next word
      Probabilities are illustrative.

      Three things stand out. Some blanks have one obvious answer and some have many, so a good guess is a probability for every candidate, not a single word. Some need a fact: you cannot finish the line about France without knowing its capital. And the last one needs biology. Anything that predicts text well has to pick up the knowledge hidden in that text.

      Two approaches

      How could a machine make the guess?

      There are two ideas. Only the second one works, and watching the first one fail is the quickest way to see why.

      1. Approach 1

        Look it up

        Keep the text. To continue a phrase, find every place it already appears and count what followed.

        Finds nothing for anything new
      2. Approach 2

        Learn it

        Keep no text. Train a network until it holds the patterns of language, then let it continue anything.

        What every LLM does

      Approach 1: look it up

      Collect a huge pile of text. To continue a phrase, find every place it appears and count which word came next. The most common follower wins. No training, no mathematics, and on short everyday phrases it genuinely works.

            Cases 3 and 4

            Long phrases almost never repeat

            Most sentences people write have never been written before, so a full-sentence lookup finds nothing at all. Shortening the phrase finds matches again, but then the guess ignores most of what you said.

            Case 4

            It cannot generalize meaning

            The corpus does say "cells with high CD3E are T cells", yet "CD3E-high cells are" finds nothing. Lookup compares letters, not meaning, so a paraphrase is as unknown as nonsense.

            Where this idea comes from

            Counting what follows a phrase is not a straw man. It is the original language model. In 1913 Andrey Markov counted vowels and consonants by hand through 20,000 letters of Eugene Onegin and showed that each letter depends on the one before it; in 1948 Claude Shannon used exactly these letter and word statistics to generate text that almost reads like English. Every lookup above is a small version of that experiment, including the moment it runs out of matches.

            Andrey Markov & Claude Shannon Counted Letters to Build the First Language-Generation Models ↗Oscar Schwartz · IEEE Spectrum · 2019

            Approach 2: learn it

            Instead of storing text, train a neural network on it. Show it a very large amount of text and let it learn the patterns of language itself: grammar, facts, typical phrasing, how an argument usually unfolds. A network that has learned these patterns can continue text it has never seen before.

            Approach 2

            Learned model

              It has seen B-cell markers in many other sentences and combines what it learned.

              One obstacle remains. A neural network does arithmetic, and text is not numbers. So before any learning can happen, text has to become numbers.

              Tokenization

              Turning text into numbers

              A tokenizer cuts text into pieces from a fixed vocabulary and replaces each piece with an integer ID. These pieces are called tokens, and they are what the model actually predicts: not words, but tokens. Common English words are one token each. Gene symbols and DNA are rare in training text, so they shatter into many small pieces.

              Why pieces, and not words or letters?

              The vocabulary has to be fixed before training starts: a finite list of symbols, each with an ID. Cutting text at single letters or at whole words both give you such a list, and both fail, in opposite directions. Subword pieces are the compromise every modern model settled on.

              The same sentence, cut three ways
              UnitVocabularyStepsWhat goes wrong
              LettersAbout 100 symbols. Nothing is ever unknown.0Sequences get long, and attention cost grows with the square of the length. The model also has to rebuild every word from its letters at every single step, instead of being handed "cells" as one thing.
              Whole wordsUnbounded. English alone has millions of forms, and biology keeps minting new symbols.0Whatever is missing from the list has no ID at all. CD79A, MALAT1, a typo, a new gene name: each one collapses into a single "unknown" token, and the model is blind to it.
              Subword piecesFixed, typically 50,000–200,000 entries, learned from data.0Nothing fundamental. Frequent words stay whole, so common text is short; anything rare is still spellable from smaller pieces. The price is that rare strings, such as gene symbols and DNA, cost several tokens each.

              Frequency buys you whole words. A piece earns its own ID by appearing often enough in the training text, which is why ␣cells is one token and CD79A is three.

              Two consequences matter for biology. Models are bad at letter-level tasks, such as counting bases or reversing a sequence, because they never see the letters. And sequences are expensive: you pay for context and time per token. Cut your own text below and watch both effects.

              Now every text is a list of integers, and the guessing game becomes: given these IDs, which ID comes next? The next question is how a network learns to play it.

              Learning

              How the model learns

              Training is the guessing game from the start of this lesson, played billions of times. Take real text, hide the next token, let the network guess, compare the guess with the truth, and nudge the network's weights so the true token becomes a little more likely. Then repeat over trillions of tokens.

              Nothing else is taught directly. Grammar, facts and marker genes are learned only because they help with the guessing.

                Attention: which earlier tokens matter

                Inside each transformer layer, attention lets every token gather information from the tokens before it. To predict what follows "are", the model needs "Cells" and the gene names, not "that". A token can never look at tokens after it.

                Click a token to see where it looks

                Weights are illustrative. A real model has dozens of attention heads per layer, each with its own pattern.

                Pretraining, then instruction tuning

                A model trained only on documents continues documents. Given a question, it often writes more questions, because that is what text full of questions looks like. Instruction tuning then trains on conversations with good answers, so the most likely continuation becomes a helpful reply. Both are still next-token prediction.

                Temperature turns scores into choices

                The network's raw scores are called logits. Softmax turns them into probabilities, and temperature T divides the logits first. Low T sharpens the distribution toward the top token. High T flattens it, so unlikely tokens get picked more often. This is why the same question gave two answers.

                Why it is called temperature

                This formula is the Boltzmann distribution from physics, with each token's energy set to minus its logit, \(E_i = -z_i\). A high logit is a deep, low-energy well, and temperature sets how often particles escape it.

                Particles in an energy landscape · one well per token
                0.80

                Each particle is one sampled answer, and each well is a token whose depth comes from its logit. The bars count particles per well; the line across each bar is the softmax probability they settle around. Temperature and logits are shared with the explorer and the sampling demo below.

                Cold · \(T \to 0\)Particles freeze in the deepest well. The model picks its top token every time.
                Warm · \(T = 1\)Particles jiggle and sometimes hop. The model samples the distribution it learned.
                Hot · \(T \to \infty\)Particles boil over every barrier. Every token approaches \(1/V\), and output turns random.

                Cold model, frozen answers. Hot model, boiling answers.

                  Context

                  The context window is the only memory

                  The model keeps nothing between requests. A chat app resends the whole transcript every turn: system prompt, every question, every answer. The context window is the maximum number of tokens one request can hold. When the transcript outgrows it, the oldest messages are dropped and the model never sees them.

                    Thinking mode

                    Thinking is more tokens before the answer

                    A reasoning model first writes intermediate text, then the answer. Nothing new happens inside: it is the same next-token loop. The extra tokens give later tokens more to attend to, which helps on problems with several steps. You pay in time and context.

                    Hands-on

                    First call

                    first_call.py
                    from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")  # any key works locally
MODEL = "qwen/qwen3-4b"  # use the identifier LM Studio shows for your model

resp = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "system", "content": "You are a concise bioinformatics assistant."},
        {"role": "user", "content": "Which cell type expresses CD14, LYZ and S100A8?"},
    ],
    temperature=0.7,
)
print(resp.choices[0].message.content)
print(resp.usage)  # prompt_tokens, completion_tokens, total_tokens

                    Exercises

                    1. Build the chat yourself

                      Keep the messages list in your own code and append every turn. This list is the context: watch prompt_tokens grow each turn.

                      chat.py
                      from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")
MODEL = "qwen/qwen3-4b"

messages = [{"role": "system", "content": "You are a concise bioinformatics assistant."}]
while True:
    user = input("you> ")
    if user in {"exit", "quit"}:
        break
    messages.append({"role": "user", "content": user})
    resp = client.chat.completions.create(model=MODEL, messages=messages)
    reply = resp.choices[0].message.content
    messages.append({"role": "assistant", "content": reply})
    print("model>", reply)
    print(f"[sent {resp.usage.prompt_tokens} tokens this turn]")
