Structured outputs for biology

Lesson 1 ended with a problem: a model answers in sentences, and a pipeline cannot use sentences. In this lesson the model fills in a fixed format that code can check. The task is a real one: naming the cell clusters of the PBMC 3k dataset.

90 min Needs LM Studio and an instruction-tuned 7B+ model Python: scanpy, openai, pydantic Data: PBMC 3k Previous: How LLMs work
The task

Give each cluster a name

A single-cell analysis groups thousands of cells into clusters and lists the genes that set each cluster apart. It does not say what the clusters are. A biologist reads the marker genes and writes down a cell type. That step is called annotation, and it is the job we will hand to a language model.

For the answers to be useful, every cluster has to come back with the same fields, filled in the same way, so that code can read them and check them.

To judge whether the model got it right, you need to know where those clusters and marker lists came from, and which choices along the way could change them. That is what the primer below covers.

After the primer

Name the clusters with a local LLM

The primer left you with an adata object: 2,638 cells in nine Leiden clusters, and a ranked marker list for each one. Now we answer its open question. A short Python file sends the markers of all nine clusters to a model running on your own computer in LM Studio, in one request, and gets back a cell type, a confidence level and a one-sentence reason for each.

  1. scanpy
    Find markersget_markers()

    Ranks the genes that set each cluster apart and keeps the top 15, as in step 09 of the primer.

  2. LLM
    Ask the modelask_llm()

    Sends every cluster's genes, the tissue and the species to LM Studio in one prompt and reads back one JSON answer.

  3. pandas
    Label cellsannotate()

    Matches each answer to its cluster, marks any skipped cluster as unknown and writes the names into adata.obs.

Setup

Before you start

This is the same LM Studio setup as in Lesson 1. If your server from there still runs, only step 4 is new.

  1. Load a model in LM StudioAny instruction-tuned model of 7B parameters or more, for example from the Qwen, Llama, Gemma or Mistral families. Smaller models often ignore the JSON format.
  2. Start the local serverIn the Developer tab, press Start server. It listens on http://localhost:1234.
  3. Copy the model namePaste it into MODEL at the top of the file, exactly as LM Studio shows it.
  4. Install the packagespip install scanpy openai. The openai package only talks to your local server; nothing is sent to OpenAI. It also installs pydantic, which we use at the end.
The code

One file, three functions

Save this as simple_anno.py next to your notebook. Read it top to bottom: settings, the prompt, then the three functions in the order they run. The model is called once for the whole dataset, not once per cluster.

simple_anno.py · 61 lines
"""simple_anno.py - name scanpy clusters with a local LLM served by LM Studio."""
import json
import re

import pandas as pd
import scanpy as sc
from openai import OpenAI

# LM Studio serves an OpenAI-compatible API on your own computer.
client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")
MODEL = "qwen2.5-7b-instruct"  # copy the model name shown in LM Studio

PROMPT = """You are an expert in single-cell biology.
Tissue: {tissue}. Species: {species}.
These are the clusters of one dataset, each with its top marker genes, most specific first:
{clusters}

Name the most likely cell type of every cluster. Reply with JSON only, one entry per cluster, like this:
{{"clusters": [{{"cluster": "0", "cell_type": "...", "confidence": "high, medium or low", "reason": "one short sentence"}}, ...]}}"""

MISSING = {"cell_type": "unknown", "confidence": "low", "reason": "no answer for this cluster"}


def get_markers(adata, groupby="leiden", n_genes=15):
    """Return {cluster: [top marker genes]} using scanpy's differential expression."""
    sc.tl.rank_genes_groups(adata, groupby, method="wilcoxon")
    df = sc.get.rank_genes_groups_df(adata, group=None)
    df = df[~df["names"].str.startswith(("MT-", "RPL", "RPS"))]  # skip mito/ribosomal genes
    return {str(c): g["names"].head(n_genes).tolist() for c, g in df.groupby("group", observed=True)}


def ask_llm(markers, tissue="unknown", species="human"):
    """Ask the local LLM to name every cluster in one request; return a list of answers."""
    clusters = "\n".join(f"Cluster {c}: {', '.join(genes)}" for c, genes in markers.items())
    prompt = PROMPT.format(tissue=tissue, species=species, clusters=clusters)
    response = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1,  # low = more consistent answers
    )
    text = response.choices[0].message.content
    text = re.sub(r"<think>.*?</think>", "", text, flags=re.DOTALL)  # drop "thinking" if present
    match = re.search(r"\{.*\}", text, flags=re.DOTALL)  # find the JSON part of the reply
    if match is None:
        return []
    return json.loads(match.group()).get("clusters", [])


def annotate(adata, groupby="leiden", tissue="unknown", species="human", n_genes=15):
    """Annotate every cluster and store the labels in adata.obs['cell_type']."""
    markers = get_markers(adata, groupby, n_genes)
    answers = {str(a.get("cluster")): a for a in ask_llm(markers, tissue, species)}
    rows = []
    for cluster, genes in markers.items():
        answer = answers.get(cluster, MISSING)  # the model may skip a cluster
        print(f"Cluster {cluster}: {answer['cell_type']} ({answer['confidence']})")
        rows.append({**answer, "cluster": cluster, "markers": ", ".join(genes)})

    table = pd.DataFrame(rows).set_index("cluster")
    adata.obs["cell_type"] = adata.obs[groupby].astype(str).map(table["cell_type"]).astype("category")
    return table
  • Why one request for all clusters? The instructions are read once instead of nine times, there is one round trip instead of nine, and the model can compare clusters with each other, for example the two CD4 T cell clusters. The price is a longer reply that the model has to keep in step with the cluster list.
  • Why JSON? A fixed format lets the code read the answer reliably instead of parsing free text. Each entry carries its cluster number, so annotate() can match answers to clusters even if the model changes the order.
  • Why MISSING? With nine answers in one reply, a model sometimes skips one, often a small cluster. That cluster gets unknown instead of crashing the run.
  • Why the two re lines? Some models "think out loud" in <think> tags or wrap the JSON in extra text. The code strips the thinking and keeps only the part between { and }.
  • Why temperature=0.1? Lower temperature makes the model pick its most likely answer, so reruns give similar labels. Lesson 1 showed what temperature does to the next-token choice.

Constrain the output

Guarantee the JSON format

Asking for JSON in the prompt works most of the time, but a model can still add a sentence before the answer, rename a key, or reply "very high" instead of "high". That is why ask_llm() needs the regular expressions and the fallback to an empty list.

LM Studio can remove the guesswork. You describe the answer as a JSON schema and send it with the request. The server then only lets the model write text that fits the schema, so every reply can be read directly.

Replace ask_llm() with this version

simple_anno.py · replaces ask_llm
SCHEMA = {
    "type": "object",
    "properties": {
        "clusters": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "cluster": {"type": "string"},
                    "cell_type": {"type": "string"},
                    "confidence": {"type": "string", "enum": ["high", "medium", "low"]},
                    "reason": {"type": "string"},
                },
                "required": ["cluster", "cell_type", "confidence", "reason"],
            },
        },
    },
    "required": ["clusters"],
}


def ask_llm(markers, tissue="unknown", species="human"):
    """Ask the local LLM to name every cluster in one request; return a list of answers."""
    clusters = "\n".join(f"Cluster {c}: {', '.join(genes)}" for c, genes in markers.items())
    prompt = PROMPT.format(tissue=tissue, species=species, clusters=clusters)
    response = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1,
        response_format={"type": "json_schema",
                         "json_schema": {"name": "annotations", "schema": SCHEMA}},
    )
    return json.loads(response.choices[0].message.content)["clusters"]
  • SCHEMA describes one object with a clusters list. Each entry has four text fields, all required. The enum limits confidence to exactly high, medium or low.
  • response_format hands the schema to LM Studio. The name is just a label for the format.
  • The cleanup is gone. No re lines and no empty-list fallback: the reply is always valid JSON, so json.loads() is enough.
  • What the schema cannot say. It can require a list of entries, but not "exactly one entry for each of clusters 0 to 8". A skipped cluster still falls through to MISSING in annotate(). The next section checks this properly.
  • Keep the prompt as it is. The schema fixes the shape of the answer, but the prompt still tells the model what each field should contain.
Not every model supports this

LM Studio notes that models below 7B parameters often fail with structured output. If you get an error, load a larger model or switch back to the original ask_llm().

Thinking models (for example Qwen3.5 or Qwen3.6) do not combine well with a schema yet. In current LM Studio versions the schema is enforced from the first token, so the model skips its thinking and the JSON arrives in reasoning_content while content is empty, which makes json.loads() fail. Turn thinking off in the model's settings, use a non-thinking instruct model, or drop response_format and use the original ask_llm(). Both bugs are still open: #1773 and #1698.

Validate what comes back

Check the content with Pydantic

The schema guarantees the shape of the reply: the right keys, the right types, one of three confidence levels. It says nothing about the content. A reply can fit the schema perfectly and still skip a cluster, answer the same cluster twice, or cite a gene the model was never shown, so the reason sounds convincing but has no evidence behind it.

Pydantic is a Python library for checking data. You describe the answer once as a Python class. Pydantic turns that class into the JSON schema for LM Studio, then checks every reply against it, including rules a schema cannot express. When a check fails, the code shows the model the error and asks again.

Replace PROMPT, SCHEMA and ask_llm() with this version

Each entry gains one field, supporting_markers: the genes from that cluster's list that the answer rests on. get_markers() and annotate() stay as they are.

simple_anno.py · replaces PROMPT, SCHEMA and ask_llm
from typing import Literal  # add these two imports at the top of the file

from pydantic import BaseModel, ValidationError, ValidationInfo, field_validator

PROMPT = """You are an expert in single-cell biology.
Tissue: {tissue}. Species: {species}.
These are the clusters of one dataset, each with its top marker genes, most specific first:
{clusters}

Name the most likely cell type of every cluster. Reply with JSON only, one entry per cluster, like this:
{{"clusters": [{{"cluster": "0", "cell_type": "...", "confidence": "high, medium or low",
  "supporting_markers": ["genes from that cluster's list"], "reason": "one short sentence"}}, ...]}}"""


class Annotation(BaseModel):
    cluster: str
    cell_type: str
    confidence: Literal["high", "medium", "low"]
    supporting_markers: list[str]
    reason: str


class Annotations(BaseModel):
    clusters: list[Annotation]

    @field_validator("clusters")
    @classmethod
    def match_the_markers(cls, clusters, info: ValidationInfo):
        """Each cluster must be answered once and cite only its own marker genes."""
        markers = (info.context or {}).get("markers", {})
        answered = [a.cluster for a in clusters]
        problems = [f"cluster {c} needs exactly one entry, found {answered.count(c)}"
                    for c in markers if answered.count(c) != 1]
        for a in clusters:
            if a.cluster not in markers:
                problems.append(f"there is no cluster {a.cluster}")
                continue
            unknown = [g for g in a.supporting_markers if g not in markers[a.cluster]]
            if unknown:
                problems.append(f"cluster {a.cluster} cites genes not in its list: {', '.join(unknown)}")
        if problems:
            raise ValueError("; ".join(problems))
        return clusters


def ask_llm(markers, tissue="unknown", species="human", retries=2):
    """Ask for every cluster in one request; retry if the answer fails validation."""
    clusters = "\n".join(f"Cluster {c}: {', '.join(genes)}" for c, genes in markers.items())
    prompt = PROMPT.format(tissue=tissue, species=species, clusters=clusters)
    messages = [{"role": "user", "content": prompt}]
    for _ in range(retries + 1):
        response = client.chat.completions.create(
            model=MODEL,
            messages=messages,
            temperature=0.1,
            response_format={"type": "json_schema",
                             "json_schema": {"name": "annotations", "schema": Annotations.model_json_schema()}},
        )
        text = response.choices[0].message.content
        try:
            return Annotations.model_validate_json(text, context={"markers": markers}).model_dump()["clusters"]
        except ValidationError as err:
            messages.append({"role": "assistant", "content": text})
            messages.append({"role": "user", "content": f"That answer has errors:\n{err}\nPlease fix them and reply again."})
    return []  # annotate() marks every cluster as unknown
  • Two classes describe the answer. Annotation is one cluster's entry and Annotations is the whole reply. Annotations.model_json_schema() builds the schema for LM Studio from them, so the hand-written SCHEMA dict is gone and the two can never drift apart.
  • Literal[...] does what enum did in the schema: only high, medium or low are accepted.
  • The validator checks the reply against the data. context={"markers": markers} passes the real marker lists into the check. Every cluster must appear exactly once, no made-up cluster may appear, and each entry may cite only genes from its own list. A JSON schema cannot express any of these rules.
  • All problems are reported at once. The validator collects every problem before it raises, so one retry can fix them all.
  • Errors go back to the model. The bad reply and Pydantic's message are added to the conversation, and the model gets up to two more tries. Models usually fix a mistake once it is named.
  • There is still a fallback. If every try fails, ask_llm() returns an empty list and annotate() marks the clusters unknown instead of stopping. Then look at the clusters by hand, or try a larger model.
Valid is not the same as correct

Validation throws out answers that are malformed or cite missing evidence. A well-formed answer with the wrong cell type still passes. The results table now has a supporting_markers column, so the dot-plot check from Run it gets easier, but you still have to do it.

Going further

Taking it further

The annotator now returns answers that code can trust to be well formed. It still leaves a lot out on purpose. Each idea below is a self-contained project for students who want to go deeper, roughly from easiest to hardest.

ImprovementWhy it helpsWhere to start
Give more context
easy		Disease, treatment or a sorted population changes what the markers mean.Add a context argument and one more line to PROMPT.
Ask several times
easy		Send the same request 5 times and keep the most common answer for each cluster. Low agreement flags unclear clusters.Raise temperature to 0.7 and use collections.Counter.
Send clusters in batches
medium		With 30 or more clusters the reply gets long and small models start to skip or mix up entries.Split markers into groups of about ten and call ask_llm() once per group.
Save answers
medium		Reruns become instant and give identical labels, which helps reproducibility.Store replies in a dict or JSON file, keyed by the prompt text.
Add known marker lists
medium		Small models remember marker biology imperfectly. Giving them reference lists to compare against reduces mistakes.Download PanglaoDB or CellMarker tables and add matching entries to the prompt.
Annotate in two rounds
medium		Broad types first, then subcluster each one (for example T cells) to find subtypes.Subset adata by cell_type, recluster, call annotate() again.
Use standard names
harder		"NK cell", "NK cells" and "natural killer cell" are the same thing. Mapping labels to the Cell Ontology gives one official name and ID (for example CL:0000623).Download cl-basic.obo, read it with obonet, match names with rapidfuzz. A second Pydantic validator can reject names that are not in the ontology.
Compare with a reference method
harder		Where two independent methods disagree is where a human should look.Run CellTypist on the same data and cross-tabulate with pd.crosstab.
